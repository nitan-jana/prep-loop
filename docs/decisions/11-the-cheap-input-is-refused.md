# The cheap input is always refused

Every session in this system has a fast, comfortable version of its input
available, and takes the expensive one instead. A self-report, a hint, a
rehearsed weakness and a favourite story are all cheap, all readily offered, and
all worthless as evidence.

Four sessions, one decision.

## The check-in does not ask how the day went

A self-report is the least reliable input available, and the system exists partly
to replace it. Asking someone what they retained returns what they remember
remembering.

So the order is fixed — **evidence, then quiz, then reschedule.** Gathering comes
first, because opening with a question the evidence could have answered teaches
the user that the answers are not checked.

What the user believes appears in exactly one place: a miss reason, recorded
**verbatim**, because that is the one thing only they know. Not editorialised,
not summarised into a category, not compared to a previous miss — the planner
needs the actual reason to place the block better, and a reason rewritten into
"low energy" has lost the part that would have helped.

Two guards on the same edge. **Silence is not a miss**: a reading block leaves no
commits, and inferring a miss from an absence of evidence is how a log becomes a
record of failure that is also wrong. And **a backfilled log leaves its quiz
section explicitly empty** rather than guessing, because a log that invents what
happened is worse than none — it looks like a record.

The check-in also refuses the retention pool. It closes a day it is still inside,
so it measures whether today survived the day; the retention question belongs to
the review, which asks it at a distance where the answer means something.

## A round never helps

Inside a round the agent is an interviewer and nothing else. The round is the
only place the system gets an **uncontaminated sample** of what the user can
produce alone, and a single hint destroys it — for that answer, and for the grade
that would have been evidence.

It is also the most tempting failure, because helping is the natural response to
someone stuck. So it is written as a prohibition rather than a principle, and
restated in the forbidden list of every session that runs a round.

The specific leaks each get named: filling the silence, supplying the term the
user is circling, offering a list of questions they can pick from, revealing the
rubric, commenting on the round that just ended, and reordering rounds to finish
on a strong one. Every one of them buys comfort with sample quality.

Verification waits for the same reason. The round ends, role drops, and **then**
the claims it surfaced get checked — the one moment both halves are available,
with the answer still live and nothing at stake.

## Onboarding pushes on the good answers too

**The first answer to any question is a resume line; the second is the truth.**
So every answer gets pushed on, including the good ones, because pushing only on
weak ones teaches the user to read the push as a verdict.

The cheap opening is "tell me about your experience", which returns the resume.
The expensive one is **enumerating first** — pulling the repositories, reading
the resume, then opening with what was found. Private repositories and forks get
looked for specifically: that is where the real work often is, and a user listing
projects from memory tends to skip them.

The weak-spot question is **inverted** for the same reason. Never "what are the
weaknesses", which returns something rehearsed; ask which project they would
steer an interviewer *away* from. And each stage closes by testing itself — two
questions back, answered from memory, because **a profile the user cannot defend
out loud is aspirational, not true.**

Missing sources never block. Everything lands `stated` and a later pass upgrades
it, so starting with nothing works and loses nothing permanently.

## A story starts from the gap

Left alone, people produce five versions of the story they most enjoy telling,
which is a bank with one story in it. So a session opens on the coverage table
and asks which question shape has nothing behind it.

The rejection bar is the same refusal applied to wording. **Improved,
streamlined, optimised, scaled, significantly** — with no number and no mechanism
— are not weak phrasings to tighten later. They are the places where the story
does not yet exist, and writing them down hides that.

Two more, both cheap to skip and expensive to have skipped. **What was rejected**
is the first thing an interviewer reaches for, because it separates someone who
made a decision from someone who implemented the only thing they knew; if nothing
was considered, the story says so, since inventing an alternative invites the
follow-up asking why it lost. And **the drill sheet is half the file** — the
narrative is rehearsed once, the follow-ups are where it holds or does not.
